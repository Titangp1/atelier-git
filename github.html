Mettre son projet sur GitHub

Dans l'atelier, GitHub est simulé. Ici, vous allez le faire pour de vrai : créer un compte, installer Git, relier un dossier de votre ordinateur à un dépôt GitHub, puis y déposer vos fichiers à chaque commit.

Comptez 15 minutes la première fois. Ensuite, publier ne prend que trois commandes.

Remplissez ces deux cases : toutes les commandes de la page s'adaptent. Rien n'est envoyé ni enregistré.

1. Compte2. Installer Git3. Se présenter4. Créer le dépôt5. Relier et envoyer6. Se connecter7. Au quotidien8. Sans terminal9. Erreurs fréquentes10. Bonus : un site en ligne

1Créer un compte GitHub

Allez sur github.com/signup, choisissez un pseudo, un email et un mot de passe, puis confirmez l'email reçu.

Activez ensuite la double authentification dans Settings → Password and authentication : GitHub la demande à tous ceux qui publient du code.

2Installer Git

Téléchargez Git for Windows sur git-scm.com/downloads/win et installez-le en gardant les options par défaut. Il installe aussi Git Bash, un terminal, et le Git Credential Manager, qui gérera la connexion à GitHub à votre place.

Ouvrez l'app Terminal et tapez git --version. Si Git manque, macOS propose d'installer les outils de développement : acceptez. Avec Homebrew, brew install git marche aussi.

Avec le gestionnaire de paquets de votre distribution, par exemple sudo apt install git sur Ubuntu ou Debian, ou sudo dnf install git sur Fedora.

Vérifiez ensuite dans un terminal :

git --version

3Se présenter à Git

Une seule fois par ordinateur. Utilisez l'email de votre compte GitHub, ou l'adresse anonyme que GitHub vous donne dans Settings → Emails si vous ne voulez pas que votre email soit public.

git config --global user.name "pseudo"
git config --global user.email "vous@exemple.fr"
git config --global init.defaultBranch main

La dernière ligne nomme main la branche de départ, comme sur GitHub. C'est la leçon Configurer Git de l'atelier.

4Créer le dépôt sur GitHub

Sur GitHub, cliquez sur + en haut à droite, puis New repository. Donnez-lui le nom mon-site, choisissez Public ou Private, et cliquez sur Create repository.

Si votre projet existe déjà sur votre ordinateur, ne cochez pas « Add a README » : un dépôt vide évite un conflit au premier envoi.

GitHub affiche alors l'adresse du dépôt :

https://github.com/pseudo/mon-site.git

5Relier votre dossier et envoyer les fichiers

Ouvrez un terminal dans le dossier de votre projet (sous Windows : clic droit dans le dossier → Open Git Bash here), puis :

# 1. Transformer le dossier en dépôt Git
git init
# 2. Préparer tous les fichiers et faire le premier commit
git add .
git commit -m "Premier commit"
# 3. S'assurer que la branche s'appelle main
git branch -M main
# 4. Déclarer le dépôt GitHub sous le nom origin
git remote add origin https://github.com/pseudo/mon-site.git
# 5. Envoyer, et retenir le lien pour la suite
git push -u origin main

Au premier git push, une connexion à GitHub vous est demandée : c'est l'étape suivante. Rechargez ensuite la page du dépôt sur GitHub : vos fichiers y sont. Entraînez-vous avant avec la leçon Publier sur GitHub.

Le projet existe déjà sur GitHub ? Récupérez-le plutôt avec git clone : le lien avec origin est déjà fait.

git clone https://github.com/pseudo/mon-site.git
cd mon-site

6Se connecter à GitHub depuis le terminal

GitHub refuse votre mot de passe dans le terminal. Choisissez une de ces trois méthodes.

Le navigateur le plus simple sous Windows

Avec Git for Windows, le Git Credential Manager ouvre une fenêtre au premier git push. Choisissez Sign in with your browser, autorisez, c'est fini : la connexion est mémorisée.

GitHub CLI Windows, macOS, Linux

Installez GitHub CLI, puis lancez la commande ci-dessous et suivez les questions : choisissez HTTPS, puis la connexion par navigateur.

gh auth login

Un jeton personnel partout

Sur GitHub : Settings → Developer settings → Personal access tokens. Créez un jeton avec l'accès Contents : Read and write sur votre dépôt. Quand le terminal demande un mot de passe, collez ce jeton. Gardez-le secret comme un mot de passe.

Utiliser une clé SSH à la place

Créez une clé, puis copiez le contenu du fichier .pub dans Settings → SSH and GPG keys → New SSH key.

ssh-keygen -t ed25519 -C "vous@exemple.fr"
cat ~/.ssh/id_ed25519.pub
# Une fois la clé ajoutée sur GitHub :
ssh -T git@github.com
git remote set-url origin git@github.com:pseudo/mon-site.git

7Au quotidien : modifier, commiter, envoyer

Une fois le lien fait, chaque séance de travail suit le même cycle :

# Récupérer ce qui a changé sur GitHub (autre ordinateur, collègue…)
git pull
# … vous modifiez vos fichiers …
git status
git add .
git commit -m "Décrit ce que vous avez changé"
git push

Pour une nouvelle fonctionnalité, travaillez sur une branche : git switch -c ma-branche, puis git push -u origin ma-branche. GitHub propose alors d'ouvrir une pull request pour la fusionner dans main.

8Déposer des fichiers sans terminal

Depuis le site : sur la page du dépôt, Add file → Upload files, glissez vos fichiers, écrivez un message en bas, puis Commit changes. Chaque dépôt de fichiers crée un vrai commit.

Avec une application : GitHub Desktop fait add, commit, push et pull avec des boutons. Pratique, mais connaître les commandes reste utile quand quelque chose coince.

9Erreurs fréquentes

Support for password authentication was removed

Vous avez tapé le mot de passe du compte. Utilisez une des méthodes de l'étape 6 : navigateur, gh auth login ou jeton.

! [rejected] main -> main (fetch first)

GitHub a des commits que vous n'avez pas. Récupérez-les en rejouant vos commits par-dessus, puis renvoyez. C'est le défi Course contre Léa.

git pull --rebase
git push
error: src refspec main does not match any

Il n'y a encore aucun commit, ou votre branche s'appelle master. Faites un commit, puis renommez la branche.

git branch -M main
git push -u origin main
error: remote origin already exists

Un origin est déjà déclaré. Changez son adresse au lieu d'en ajouter un.

git remote set-url origin https://github.com/pseudo/mon-site.git
fatal: refusing to merge unrelated histories

Le dépôt GitHub a été créé avec un README alors que votre projet avait déjà des commits. Réunissez les deux histoires une fois :

git pull origin main --allow-unrelated-histories
git push -u origin main
J'ai envoyé un mot de passe ou une clé par erreur

Changez ce mot de passe ou révoquez cette clé tout de suite : le supprimer dans un nouveau commit ne suffit pas, il reste dans l'historique. Ajoutez ensuite le fichier au .gitignore, comme dans le défi Fuite de clé.

10Bonus : mettre un site en ligne gratuitement

Si votre dépôt contient un index.html, GitHub Pages peut le publier. Dans le dépôt : Settings → Pages, source Deploy from a branch, branche main, dossier / (root), puis Save.

Une à deux minutes plus tard, votre site est en ligne, et chaque git push le met à jour :

https://pseudo.github.io/mon-site/

C'est exactement comme ça que l'Atelier Git est publié.
